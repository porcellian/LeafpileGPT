# Specification Coverage Matrix

This matrix maps the supplied standards to planned implementation areas and acceptance tests. Update implementation and test references as tasks land. No standard requirement is complete until its behavior and edge cases have automated coverage or a documented manual acceptance test.

- **VAR:** `call` / `call_vs`, `storew`, `storeb`, `put_prop`, `sread` / `aread`, `print_char`, `print_num`, `random`, `push`, `pull`, `split_window`, `set_window`, `call_vs2`, `erase_window`, `erase_line`, `set_cursor`, `get_cursor`, `set_text_style`, `buffer_mode`, `output_stream`, `input_stream`, `sound_effect`, `read_char`, `scan_table`, `not`, `call_vn`, `call_vn2`, `tokenise`, `encode_text`, `copy_table`, `print_table`, `check_arg_count`.

| Requirement | Implementation | Generated coverage |
|---|---|---|
| Run scripted routes through the shared VM without desktop initialization | `ZMachineReplayRunner` uses `ZMachineExecutionState`, `ZMachineInstructionDecoder`, and `ZMachineOpcodeExecutor`; route input provides commands, defined key values, automatic MORE acknowledgements, a deterministic host random seed, and an instruction limit. | `ZMachineReplayTests` runs generated V1–V8 stories, a V5 line-input route, route exhaustion, and an instruction limit. |
| Produce deterministic machine-readable results and opcode traces | `ZMachineReplayResult` reports completion state, story identity, captured output and hash, final PC and Quetzal state hash, input/MORE counts, and opcode inventory. | Replay local story routes without requiring licensed stories in CI | `LeafpileGPT.Replay` reads route JSON, resolves the story path relative to that route, supports standalone stories and Blorb Z-code, emits JSON, can write an optional JSONL trace, and runs all route files in stable filename order. `.agent/regression-routes/` remains ignored. | The replay executable references Core only; generated fixtures exercise route behavior in CI, including CLI paths with spaces, invalid stories, and route-directory execution. ## App-data and preferences

`AppDataPaths` places per-user storage beneath `Environment.SpecialFolder.LocalApplicationData` in the `LeafpileGPT/` directory and creates `Save/` and `Preferences/`; structured runtime logs are stored under `Logs/` when first written. `UserPreferencesStore` persists separate Play Game, Save, and Restore directories and the runtime error-reporting policy as versioned JSON; Save and Restore initially point to `Save/`, and error reporting defaults to first-per-type. Generated xUnit fixtures cover layout, persistence, independent updates, error-policy defaults, and invalid preference files.

## Desktop startup and file menu

Task 24 passes the optional desktop lifetime arguments into the story loader; no argument leaves the app without a loaded story. Launch arguments support quoted paths with spaces and join multiple path tokens for unquoted paths. Play Game, Save, Restore, Restart, and Exit appear in the requested order; Save/Restore/Restart are disabled until loading succeeds. Story selection and Quetzal file dialogs use independent persisted directories. Standalone Z-code and Blorb Z-code executables can load; invalid or missing files produce a detailed dialog while leaving any previously loaded story intact. Generated xUnit tests cover argument resolution and story-file paths with spaces, invalid files, and missing files.

Task 25 adds a fixed-width blue-and-white story display with bottom-anchored, scrollable transcript output; the prompt remains at the bottom-left. The location is shown left-aligned and score/moves right-aligned in a status strip below the menus, with a distinct app-status bar below the game area. Task 26 connects the display to a live VM session: submitted lines feed asynchronous VM reads; VM output, status, and screen operations update the display; Quetzal saves can be captured during input and restores/restarts cancel pending reads at safe points; Blorb PNG/JPEG images are placed in the screen; stream-2 output is written lazily to per-session text files under app-data `Transcripts/`. Generated tests cover input, save storage, transcript failure, live execution, save capture during a pending read, and restore while a read is pending. A local-only Zork I smoke run verified startup output and the `look` response. The desktop routes Blorb sound requests to a status message but has no audio playback backend; its capability flag therefore remains disabled.
